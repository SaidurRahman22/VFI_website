# VFI — UI/Backend Audit

**Date:** 2026-08-17
**Scope:** every screen and interactive control across all four surfaces.
**Method:** read-only static audit. For each control: find its markup, follow its
JavaScript handler, then confirm the endpoint exists in the Laravel routes and that
its controller/service method is real.

**Verdicts**

| Verdict | Meaning |
|---|---|
| **WORKS** | Calls a real endpoint (or navigates somewhere real) that exists |
| **DECORATION** | Wired to nothing, or only shows a toast; static markup that never updates |
| **BROKEN** | Calls something that does not exist, errors, or is unreachable |

**Rough totals across all surfaces:** 213 works · 96 decoration · 19 broken

> Counts are indicative (they tally verdict words in the tables below), not a precise census.
> The tables are the authority.

**Read-only by design — appropriate?** Applications, Agencies, Document reviews, Partner applications, GDPR requests, Disclosures, Contact enquiries all have index-only pages with row/toolbar actions as the whole write surface. That is the right call for six of them (every write goes through one guarded, audited service). The gap is Applications, per above.

**Service-call mismatches:** none found. Every action's target exists with a matching signature — `ApplicationReviewService::transition/addNote`, `AgencySuspensionService::suspend/close/reinstate`, `DocumentReviewService::verify/reject/reopen`, `PartnerReview::approve/reject/requestMoreInfo`, `RoleAssignmentService::grant/revoke`, `DataSubjectExportService::export`, `DataSubjectErasureService::preview/erase`, `DisclosureService::record`, `StaffAccessService::openStudent`, `StepUp::assert`. Both `url()` actions resolve to real named routes (routes/web.php:84, 90) with real controller methods.

**Blade views:** only `resources/views/filament/pages/university-defaults.blade.php`. It uses `$this->form` (resolved by `ResolvesDynamicLivewireProperties::__get`) and `wire:submit="save"` -> `UniversityDefaults::save()` (line 97). Both exist.

**Access-control gap (not tooltips):** Filament is non-strict, and `get_authorization_response` allows when no policy exists (filament/src/helpers.php). Only the 10 content models have a policy. So `Applications`, `Agencies`, `Document reviews`, `Universities`, `Contact enquiries` and the `University page defaults` page are reachable by **all five** admin-panel roles — a `content_editor` can suspend an agency, verify a passport and move any agency's case.

**Resources with NO helperText / description / modalDescription anywhere:** all 10 content resources (Blogs, Events, NewsItems, Photos, PpDocs, PpEmails, PpManagers, PpNotifs, PpQuicklinks, PpUpdates), plus `ContactEnquiries` and `Universities`' table/infolist columns. Worst cases: `PpEmailForm` (`subject`, `date` — `date` is a bare TextInput), `PpUpdateForm` (`flag`, `sub`), `PhotoForm` (`img_id`, `alt`), and every `img_id` field. The Phase 9 resources are well documented by contrast.

**Parse check:** `php -l` (PHP 8.4.24) on all 95 files under `backend/app/Filament` plus `backend/app/Providers/Filament/AdminPanelProvider.php` — no syntax errors in any file.

**The one real bug:** `D:\project\VFI_website\backend\app\Filament\Resources\StudentLookup\Tables\StudentLookupTable.php:24-27`

```php
->modifyQueryUsing(fn ($query) => $query->when(
    blank(request()->input('tableSearch')),
    fn ($q) => $q->whereRaw('1 = 0'),
))
```

`$tableSearch` is a Livewire property bound with `wire:model` (filament/tables search-field.blade.php:9) and carries no `#[Url]` and no `queryString` mapping in Filament 4.12.6 / Livewire 3.8.3. Livewire updates POST to `/livewire/update`, so `request()->input('tableSearch')` is always null and `whereRaw('1 = 0')` is applied on every render. The Student lookup screen returns zero rows no matter what is typed, and both of its row actions are consequently unreachable. Fix is `$livewire->getTableSearch()` (or the `$livewire->tableSearch` property) instead of `request()`.

Root cause, one line: `js/store.js` never calls `window.VFIApi` — grep for `VFIApi|fetch(` in store.js matches only a comment at line 12. Every read is `SEED`/`localStorage` (store.js:286-307) and every write is `localStorage.setItem(LS_KEY, …)` (store.js:309-312). `/api/admin/me` is the only admin endpoint the panel touches.

Second-order effect: public pages *do* load `/api/content/bootstrap.js`, but `store.js:303-307` resolves `read() || bootstrapData() || SEED` — localStorage wins. So on the editor's own machine the site appears to update, and on every other machine nothing changed.
